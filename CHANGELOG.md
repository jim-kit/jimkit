# Changelog

Format: [Keep a Changelog](https://keepachangelog.com/). Until 1.0 the addon API may change between minor versions.

## [0.1.0] - Unreleased

### Added
- **Kits.** Add tools and looks from GitHub while Jimkit runs. The Kits screen lists the registry (ratings, versions, reviews), accepts a pasted `user/name` or GitHub link, shows what an install would do before it does it, and updates, switches off and removes what was added. New tools appear without a rebuild or restart. Downloads come only from GitHub releases and are checked against the hash the registry recorded. `JIMKIT_KITS=off` disables adding and removing; `JIMKIT_REGISTRY` points at another registry. See [docs/kits.md](docs/kits.md).
- **Looks are kits too.** Basic is part of the core; Paper, Glass and Metro are theme kits that ship in the image and can be switched off. A theme kit is a `package.json` and one stylesheet (every rule scoped to its theme, no `@import`, no external `url()`), and it can bring its own home-screen layout written against `useLayout()`; Metro's Start screen is one. `./install/install.sh --minimal` (or `--themes basic`) installs with only Basic on. Each look comes in dark and light, with seven accent colours (Ink among them) or any colour you pick; a colour too close to the page's own is moved away from it. See [docs/themes.md](docs/themes.md) and [docs/layouts.md](docs/layouts.md).
- **One text editor** for plain text, Markdown, JSON and YAML. The kind of document follows the file (or the switch at the bottom); JSON and YAML get Format, Minify, conversion to the other, indent and sorted keys, a live check and a tree with path queries. "New Markdown / JSON / YAML document" are quick actions in the tool's ⋮ menu and in search (`quick` and `aliases` in a manifest, [docs/addons.md](docs/addons.md)). JSON is reprinted without changing big numbers or `1.0`.
- **Send to…** Anything that makes a file (the converter, the text editor) can hand it to the tools that take its format (`host.offer(files)`, and `fileActions[].accept` as the list of types a tool supports).
- **Home screen**: a command bar (type to find a tool, `/` focuses it, Enter opens the first match, drop or paste a file to see what takes it); a ⋮ menu and right-click or long-press menu on tools, categories and recents (open, open in a new tab, copy link, favourite, colour, move to the top, sort A to Z, fold up, hide with Undo); favourites and a colour per tool; edit mode to reorder and hide by dragging or with buttons. `?tool=hash` opens a tool and Back closes it. Every tool's header has a ⋮ menu of its own.
- **Icon motion**: tool icons move when their card is pointed at or focused. The built-in icons have their own motion, any other icon is drawn in stroke by stroke, and a tool can pick one with `iconAnimation` ([docs/icons.md](docs/icons.md)). Metro and reduced motion stay still.
- **The `jimkit` command** for Docker and Proxmox installs: `update` (with `--check` and `--yes`), `status`, `version`, `logs`, `restart` and `delete` (container, image and command by default; `--data`, `--files` or `--all` for more, with a plan, a question, `--dry-run` and a copy of `.env` and your settings first). An update builds the new image while the old one keeps serving, swaps, waits for a healthy answer and goes back by itself if it does not get one; `.env` and settings are saved to `backups/` first. See [docs/install.md](docs/install.md).
- **Update notice** in the app: a dot on Settings and an Updates section when a newer version exists, for visitors on your network only. One request to GitHub at most every 12 hours; `JIMKIT_UPDATES` points it elsewhere or turns it off. `/api/health` and `/api/update` report the version.
- **Website** (`apps/site`, not part of the Docker image): a static page with the real tools running in it, the docs and the changelog built from the repository, a directory of the built-in and community kits with a page for each, search, and forms to submit a kit and to write a review (sign in with GitHub), its own search-engine metadata and sitemap, and a Dockerfile for hosting it.
- Core app: sessions with three tiers, limits, unlock code, records, queue, and the addon runtime with a generated registry. Sizes and durations in the config file can be written as `"512MB"`, `"20GB"`, `"4h"`, `"90m"`.
- **devtools** addon: regex tester, UUID/ULID/NanoID/password generators, timestamps and time zones, colour converter with contrast checker, QR codes (SVG/PNG), cron explainer, number bases and byte sizes, URL parser.
- **text** addon: the editor above, a bounded-memory diff and encoders (Base64, URL, Unicode, JWT and more). **hash**: worker-based streaming, HMAC, compare with a given hash. **image**: crop, rotate, resize, text, export at any size. **convert**: ffmpeg, ImageMagick, LibreOffice, pandoc, poppler and librsvg, with the UI offering only conversions that exist.
- Addons can declare settings in their manifest; they appear in the Settings panel and are validated on save. `@jimkit/sdk/testing` has `createTestContext()` and `callRoute()` for testing server code. `node cli/jimkit.mjs kits pack` and `@jimkit/pack` build a kit into one `jimkit-kit.json` for a GitHub release; `kits new` also writes a release workflow.
- `lite` and `full` Docker images, `install/install.sh` (with `--bind`, `--behind-proxy`, `--dry-run`, `--minimal`), `install/proxmox-lxc.sh`, and `node cli/jimkit.mjs doctor`, which checks the proxy setting against the bind and the traffic it has seen.

### Security
- Who counts as "on your network" is decided from the connection, not from headers. Behind a reverse proxy only the address the proxy wrote is believed; `--behind-proxy` publishes the port on 127.0.0.1 only (`--bind` or `JIMKIT_BIND` to change it); `X-Forwarded-Host` is only trusted when a proxy is in front.
- The `Host` header has to be a name the instance knows (`JIMKIT_ALLOWED_HOSTS`, or the defaults in [docs/security.md](docs/security.md)); a request under another name is public, whatever its address. This closes DNS rebinding.
- Request bodies are read with a size cap, IPv6 visitors are limited per /64, and malformed CIDR entries are rejected instead of widened.
- Parallel guesses can't slip past the unlock limiter; parallel uploads can't overrun the file, size, daily and disk limits; stalled uploads are dropped after two minutes.
- The converter refuses spreadsheets that call `WEBSERVICE`, runs LibreOffice with its network closed, caps the size of data conversions, video output and rendered pages, and runs every step as a child process with a minimal environment.
- Strict Content-Security-Policy, and a read-only, non-root container with no capabilities.
